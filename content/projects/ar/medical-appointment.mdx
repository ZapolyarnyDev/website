## المهمة

تطوير نظام ذاتي الاستضافة لحجز مواعيد المرضى لمؤسسة، مع التكامل مع شبكة الشركة

## ما يستطيع النظام فعله

- يمكن للمريض اختيار الطبيب والتخصص والموعد المتاح، ثم تأكيد الحجز في حسابه الشخصي؛
- حجز مواعيد المرضى عبر حساب الاستقبال؛
- يرى الطبيب مواعيده ويغيّر إتاحة المواعيد وينهي الزيارة؛
- إدارة الجداول وحسابات الموظفين عبر حساب رئيس الأطباء.

## بنية التطبيق

بُني جانب الخادم باستخدام Java وSpring Boot. تستقبل متحكمات HTTP الطلبات من الواجهتين العامة والداخلية التابعة للشركة، وتتحقق من صحة البيانات. يتحقق منطق الأعمال من إتاحة الموعد، ويتيح إنشاء الحجوزات وإلغاءها

تُخزّن البيانات في قاعدة PostgreSQL. تُستخدم jOOQ للاستعلامات، واستُخدمت Flyway لترحيل قاعدة البيانات

![مخطط العلاقات بين المرضى والأطباء والجداول والحجوزات](/images/portfolio/medical-appointment/data-model.png)

يتضمن النشر Dockerfile وDocker Compose وCaddy بوصفه خادمًا وكيلاً عكسيًا. وُثّقت واجهة REST API باستخدام OpenAPI؛ وأُضيفت اختبارات تكامل للسيناريوهات الحساسة

## Active Directory وKerberos

لا يتصل التطبيق مباشرةً بـActive Directory، بل يمر عبر Keycloak بوصفه مزوّد OIDC. يتلقى Spring Security رمز OIDC/JWT، ويحوّل الأدوار ويربط الحساب بملف محلي للمريض أو الموظف.

في وضع _ad_ يتصل Keycloak بـActive Directory عبر LDAP federation. يوفّر الإعداد Kerberos آليةً مفضّلة، بحيث يمكن لمستخدم Windows داخل شبكة النطاق تسجيل الدخول بسلاسة باستخدام حساب النطاق
